# Extensions pre-installed into the editor.
#
# code-server resolves extensions through Open VSX (open-vsx.org), not the
# Microsoft marketplace. Check that an entry exists before adding it:
#   curl -s -o /dev/null -w '%{http_code}\n' https://open-vsx.org/api/<namespace>/<name>
#
# EXT_SET in .env decides how far down this file the seeding goes.
#   minimal : what containerlab work needs
#   network : + device configs, diagrams, python, operational tooling
#   full    : + LLM assistants (default)

# --- SET minimal ---
# The containerlab extension: topology tree, deploy/destroy, node attach, graph.
# It shells out to the containerlab CLI, which is why the editor container has
# the host binary mounted. https://containerlab.dev/manual/gui/vsc-extension
srl-labs.vscode-containerlab
# Schema validation and completion for .clab.yml. Pairs with yaml.schemas in
# settings.json.
redhat.vscode-yaml

# --- SET network ---
# Device config syntax and language servers, one per vendor.
#
# Cisco. Bound to *.cfg and *startup-config* by files.associations in
# settings.json. Arista EOS and FRR configs are close enough to IOS that this
# highlights them too if you map their filenames the same way.
y-ysss.cisco-config-highlight
aswertus.cisco-ios-lsp
# Nokia SR Linux and SR OS. From srl-labs, same authors as containerlab, and
# SR Linux is the NOS in most of the official examples.
srl-labs.sr-vscode
# Juniper Junos.
codeout.vscode-junos
# MikroTik RouterOS, for the mikrotik_ros kind.
TIKOCI.lsp-routeros-ts
#
# Searched Open VSX and found nothing for Arista EOS, SONiC, VyOS, FRR, Cisco
# NX-OS, Huawei, Palo Alto or Fortinet -- several phrasings, no hits. Anything
# for those on the Microsoft marketplace is out of reach: code-server resolves
# extensions through Open VSX. EOS and FRR are close enough to IOS that the
# Cisco highlighter covers them once files.associations maps their filenames.
# If one does appear, add it here rather than installing it by hand -- the list
# is what an air-gapped host and a rebuilt host both get.

# YANG models, for gNMI and NETCONF work rather than device configs.
typefox.yang-vscode
# SNMP MIBs.
golangsnmp.gomib-vscode
# The host's own files -- sshd_config, iptables, systemd units, /etc/hosts,
# fstab, interfaces. The editor terminal is the host, so these get edited here.
CyberBookAS.system-syntax
# CSV and TSV: interface lists, address plans, anything pasted out of a report.
mechatroner.rainbow-csv
# Topology diagrams. drawio-diagrams-editor pulls vscode-drawio in as a
# dependency; both are listed so the versions are pinned by this file.
hediet.vscode-drawio
electropol-fr.drawio-diagrams-editor
# Python. Pylance is proprietary and absent from Open VSX, so basedpyright
# supplies IntelliSense. Leaving it out gives you an extension that is installed
# but silently has no completion, which is hard to diagnose.
ms-python.python
detachhead.basedpyright
charliermarsh.ruff
# Lab scripts and container work.
docker.docker
eamodio.gitlens

# --- SET full ---
# LLM assistants. Each needs its own API key or sign-in.
Anthropic.claude-code
Continue.continue
saoudrizwan.claude-dev
