# IP 대역 관리

## Docker 자동 할당이 containerlab 기본 대역을 삼킵니다

Docker 는 네트워크를 만들 때 `172.17.0.0/12` 에서 `/16` 씩 순서대로 할당합니다. 실제로 네트워크를 연달아 만들어 보면 이렇게 나갑니다.

```
첫 번째  → 172.18.0.0/16
두 번째  → 172.19.0.0/16
세 번째  → 172.20.0.0/16     ← containerlab 기본 관리망 172.20.20.0/24 를 통째로 포함
```

세 번째가 문제입니다. containerlab 기본 관리망은 `172.20.20.0/24` 인데 `172.20.0.0/16` 안에 들어갑니다. 그러면 랩 배포가 이렇게 실패합니다.

```
Error response from daemon: invalid pool request: Pool overlaps with other one on this address space
```

네트워크를 서너 개만 만들어도 발생할 수 있고, 이 레포의 스택과 무관하게 이미 존재하는 위험입니다.

## 자동 할당 범위를 좁게 가둡니다

`/etc/docker/daemon.json` 에 추가합니다. 기존 설정이 있으면 덮어쓰지 말고 병합하십시오.

```json
{
  "default-address-pools": [
    { "base": "172.30.0.0/16", "size": 24 }
  ]
}
```

```sh
sudo systemctl restart docker
docker info --format '{{json .DefaultAddressPools}}'
```

이렇게 하면 자동 할당되는 모든 도커 네트워크가 `172.30.0.0/16` 안의 `/24` 로만 생깁니다. `/24` 가 256개이므로 실사용에 충분합니다.

```
첫 번째  → 172.30.1.0/24
두 번째  → 172.30.2.0/24
세 번째  → 172.30.3.0/24
```

랩은 172.16–172.29, 172.31, 10/8, 192.168/16 을 자유롭게 쓸 수 있고, 사용자에게 알려줄 규칙은 **`172.30.0.0/16` 만 피하라**는 한 줄로 끝납니다.

이 설정은 **자동 할당**에만 적용됩니다. 랩이 `ipv4-subnet` 을 명시하면 이 풀과 무관하게 그 대역을 씁니다. 이미 사용 중인 대역은 Docker 가 알아서 건너뛰므로, 스택의 compose 네트워크를 풀 안의 특정 `/24` 로 고정해도 자동 할당과 충돌하지 않습니다.

## 랩마다 관리망을 분리하기

containerlab 기본 관리망은 여러 랩이 **공유합니다.** 두 랩이 기본 관리망에서 같은 `mgmt-ipv4` 를 쓰면 두 번째 배포가 실패합니다.

```
Error response from daemon: failed to set up container networking: Address already in use
```

랩마다 관리망 이름과 대역을 따로 주면 해결됩니다.

```yaml
mgmt:
  network: labA-mgmt
  ipv4-subnet: 172.30.101.0/24
```

내부 노드를 전부 `network-mode: none` 으로 두면 관리망이 아예 생기지 않으므로 이 문제도 함께 사라집니다. [랩 격리](lab-isolation.ko.md) 를 보십시오.

## 데이터플레인은 애초에 겹치지 않습니다

관리망과 달리 **데이터플레인 링크는 랩마다 완전히 분리됩니다.** 링크는 veth 쌍이고 양 끝이 각 컨테이너의 네트워크 네임스페이스 안에만 있어서, 서로 다른 랩의 링크는 L2 도메인이 겹치지 않습니다.

같은 MAC 과 같은 IP 를 쓰는 랩 두 개를 동시에 띄워도 아무 문제가 없습니다. 실제로 확인한 결과입니다.

```
clab-labA-r1  1.1.1.1/30  00:11:22:33:44:01
clab-labA-r2  1.1.1.2/30  00:11:22:33:44:02
clab-labB-r1  1.1.1.1/30  00:11:22:33:44:01     ← 완전히 동일
clab-labB-r2  1.1.1.2/30  00:11:22:33:44:02
```

양쪽 모두 내부 통신이 정상이고, 한쪽 랩의 노드를 정지시켜도 다른 랩은 영향을 받지 않습니다. 즉 같은 실제 장비 config 를 여러 벌 동시에 돌릴 수 있습니다.
